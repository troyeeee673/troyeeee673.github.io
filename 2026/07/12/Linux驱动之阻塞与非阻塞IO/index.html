Linux驱动之阻塞与非阻塞IO

发表于 2026-07-12 分类于 Linux系统驱动开发

一、Linux 阻塞和非阻塞 IO

1.1 阻塞与非阻塞简介

阻塞:当资源不可用的时候，应用程序就会挂起。当资源可用的时候，唤醒任务。应用程序使用 open 打开驱动文件，默认是阻塞方式打开。

非阻塞: 当资源不可用的时候，应用程序轮询查看，或放弃。会有超时处理机制。应用程序在使用 open 打开驱动文件的时候，使用 O_NONBLOCK。

·1.2 等待队列

1、等待队列头
wait_queue_head_t 需要定义一个。定义以后使用 init_waitqueue_head 函数初始化。或者使用宏 DECLARE_WAIT_QUEUE_HEAD。

2、等待队列项
wait_queue_t 代表等待队列项，或者使用宏 DECLARE_WAITQUEUE(name, tsk)。

3、添加队列项到等待队列头
add_wait_queue 函数

4、移除等待队列项
资源可用的时候使用 remove_wait_queue 函数移除。

5、唤醒
wake_up 唤醒

1.3、轮询（非阻塞方式）

  • select/poll/epoll 是 Linux 内核提供的轮询机制，应用程序可以使用这些机制来轮询文件描述符的状态。

select、poll、epoll 函数原型、参数总结

一、select（POSIX 标准，多路IO复用）

1. 函数原型

2. 参数详解

  1. nfds
    待监听文件描述符的最大值 + 1；select 内部会遍历 0 ~ nfds-1 所有fd。
  2. readfds
    读事件fd集合：监听fd是否可读（有数据、连接关闭、异常）；传入NULL不监听读。
  3. writefds
    写事件fd集合：监听fd是否可写（缓冲区有空位）；传入NULL不监听写。
  4. exceptfds
    异常事件fd集合：监听带外数据；传入NULL不监听异常。
  5. timeout
    超时时间结构体 struct timeval { long tv_sec; long tv_usec; }
    • NULL：永久阻塞，直到有事件触发
    • tv_sec=0 && tv_usec=0：非阻塞，立即返回，轮询检测
    • 大于0：最多阻塞指定时长，超时返回0

3. 返回值

  • 0：就绪fd总个数

  • 0：超时，无事件
  • -1：出错，errno置位

配套操作宏

缺点

  • fd集合上限FD_SETSIZE（默认1024），无法突破
  • 每次调用需重置fd集合，内核/用户态频繁拷贝fd
  • 内核线性遍历所有fd，性能随fd数量线性下降

二、poll（优化版select，无fd数量硬限制）

1. 函数原型

2. 核心结构体 struct pollfd

常用事件宏：

  • POLLIN：可读；POLLOUT：可写
  • POLLERR：错误；POLLHUP：挂断

3. 参数详解

  1. fds
    pollfd结构体数组，存放所有待监听fd与事件。
  2. nfds
    数组元素个数，无1024硬上限。
  3. timeout
    单位：毫秒ms
    • -1：永久阻塞
    • 0：非阻塞轮询

    • 0：阻塞指定毫秒后超时

4. 返回值

  • 0：就绪fd数量

  • 0：超时无事件
  • -1：调用失败

对比select改进

  • 取消fd数量1024限制
  • 入参/出参分离（events/revents），不用每次重置监听集合

仍存在缺陷

  • 每次调用仍需将全部fd数组拷贝到内核
  • 内核线性扫描全部fd，高并发场景性能差

三、epoll（Linux专属，高性能IO多路复用）

epoll分为3个API：epoll_create、epoll_ctl、epoll_wait

1. epoll_create 创建epoll实例

  • size：旧版本提示监听fd预估数量，新版内核忽略，传任意正数即可
  • 返回值：epoll文件描述符（epfd），失败返回-1

2. epoll_ctl 注册/修改/删除fd监听事件

参数
  1. epfd：epoll_create返回的句柄
  2. op：操作类型
    • EPOLL_CTL_ADD：新增fd监听
    • EPOLL_CTL_MOD：修改已有fd监听事件
    • EPOLL_CTL_DEL：删除fd监听
  3. fd：要操作的文件描述符
  4. event：结构体，描述监听事件
  • EPOLLET：边缘触发（ET，高性能默认）；无则水平触发LT

3. epoll_wait 阻塞等待事件就绪

参数
  1. epfd：epoll句柄
  2. events：输出数组，内核存放就绪fd事件
  3. maxevents：events数组最大容量，一次最多返回多少就绪fd
  4. timeout：单位ms
    • -1：永久阻塞
    • 0：非阻塞轮询

    • 0：定时阻塞

返回值

  • 0：就绪fd个数

  • 0：超时无事件
  • -1：出错

epoll核心优势

  1. 红黑树存储监听fd，仅拷贝就绪fd到用户态，减少数据拷贝
  2. 事件回调机制，内核仅遍历就绪fd，时间复杂度O(1)
  3. 无fd数量硬性上限，仅受系统文件句柄总数限制

四、三者核心对比速记表

特性 select poll epoll
平台 跨平台POSIX 跨平台POSIX Linux独有
fd上限 默认1024，不可动态改 无硬上限 无硬上限
数据拷贝 每次调用全量拷贝fd集合 每次全量拷贝pollfd数组 仅拷贝就绪fd
内核检索 线性遍历全部fd O(n) 线性遍历全部fd O(n) 仅遍历就绪fd O(1)
触发模式 仅水平触发LT 仅水平触发LT LT/ET边缘触发可选
适用场景 少量fd，简单兼容场景 中等fd，需要突破1024限制 高并发海量fd（服务端首选）
