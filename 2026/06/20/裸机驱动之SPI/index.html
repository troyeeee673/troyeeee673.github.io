裸机驱动开发之SPI

发表于 2026-06-20 更新于 2026-06-27 分类于 Linux裸机驱动开发

IMX6ULL 的 SPI 总线与 ICM-20608 六轴传感器

SPI 是嵌入式开发中另一条与 I²C 齐名的常用总线。本篇笔记将先梳理 SPI 协议本身及 IMX6ULL 的 ECSPI 控制器特点，再结合板载的 ICM-20608 六轴传感器，记录从协议到外设驱动的完整思路。

一、SPI 协议

比起 I²C，SPI 有两大突出优势：速度快（可达几十甚至上百 MHz）和全双工。它同样支持一个接口挂载多个外设，但选通方式不是靠地址，而是靠独立的片选信号（CS）——通信前拉低对应外设的 CS 引脚即可。

  • 工作模式：由 CPOL（时钟极性）和 CPHA（时钟相位）组合出四种模式，实际最常用的是 CPOL=0, CPHA=0（即 Mode 0）。
  • 硬件连接：我使用的 ALPHA 开发板上，是通过 ECSPI3 连接了一块六轴传感器，具体引脚对应关系如下：
ECSPI3 信号 功能 对应 IMX6ULL 引脚
SCLK 串行时钟 UART2_RX
MOSI 主出从入 UART2_CTS
MISO 主入从出 UART2_RTS
SS0 硬件片选0 UART2_TXD

IMX6ULL 的一个 SPI 主接口最多可提供 4 个硬件片选（SS0~SS3）。

二、IMX6ULL 的 ECSPI 控制器

IMX6ULL 的 SPI 外设全称是 ECSPI（Enhanced Configurable SPI），支持全双工、主从模式可配。下面是与驱动开发直接相关的几个核心寄存器。

2.1 控制与配置寄存器

  • CONREG：主控制寄存器。

    • bit0：SPI 使能位，置 1 开启模块。
    • bit3：突发访问控制，置 1 表示一旦向 TXFIFO 写数据，立刻启动发送。
    • bit7:4：通道主从模式配置，我们用的通道 0（SS0），需将 bit4 置 1，设为主模式。
    • bit19:18：当前通信通道选择，设为 00，即通道 0。
    • bit31:30：突发访问数据长度，设为 7，对应 8 位（1 字节）传输。

  • CONFIGREG：具体时序与特性配置。

    • bit0 (PHA)：设为 0，在第一个时钟边沿采样数据。
    • bit4 (POL)：设为 0，空闲时 SCLK 为低电平。
    • bit16：设为 0，空闲时数据线保持高电平。
    • bit20：设为 0，空闲时 SCLK 为低电平。

2.2 状态与周期寄存器

  • STATREG：状态寄存器，流程控制全靠它。

    • bit0：TXFIFO 空标志，发送前必须等待此位为 1。
    • bit3：RXFIFO 就绪标志，接收前必须等待此位为 1。

  • PERIODREG：传输时序控制。

    • bit14:0：片选建立后的等待时间，设为 0x2000。
    • bit15：等待时钟源选择，设为 0，选 SPI 时钟。
    • bit21:16：硬件片选延时，可设 0~63，我们使用软件片选，故直接设为 0。

2.3 时钟树配置

这是决定 SPI 通信速率的关键，时钟链路需要逐级来看：

  1. 时钟源：来自 pll3_sw_clk = 480MHz / 8 = 60MHz。需确认 CSCDR2 寄存器的 bit18 为 0，选择此时钟源；bit24:19 设为 0，一级分频系数为 1。因此，进入 ECSPI 模块的根时钟是 60MHz。

  2. 模块内部分频：在 ECSPI_CONREG 寄存器中还有两级分频：

    • 前级分频：bit15:12，可配置 1~16 分频。
    • 后级分频：bit11:8，按 2^n 分频，n=0~15。

最终的 SCK 时钟频率就是由这个公式决定的，我们可以根据需要灵活计算。

三、ICM-20608 六轴传感器

板载的六轴传感器是 ICM-20608，它内部集成了三轴陀螺仪和三轴加速度计。

3.1 核心特性

  • 两个 16 位 ADC，分别处理陀螺仪和加速度计数据，分辨率可配置。
  • 双接口：支持 I²C（最高 400kHz）和 SPI（最高 8MHz），我们在这里使用 SPI 通信。
  • 身份识别：WHO_AM_I（0x75） 寄存器，读取默认值通常为 0xAF（注意：ICM-20608D 型号可能为 0xAE），这是验证通信是否正常的首选手段。
  • 数据读取：核心的传感器数据存储在一段连续的地址空间 0x3B ~ 0x48 内，只需依次读出，即可解算出三轴加速度和三轴角速度的实时值。

3.2 驱动开发要点

在裸机或 Linux 下驱动这个传感器，核心流程可概括为：

  1. 初始化 ECSPI3，按照上文配置好时钟、模式和片选。
  2. 读取 WHO_AM_I 寄存器，确认设备存在且通信无误。
  3. 配置传感器的工作模式、量程及采样率。
  4. 在主循环中批量读取 0x3B~0x48 的原始数据，再根据量程换算成实际的物理量。

从 SPI 协议、IMX6ULL 控制器特性，到 ICM-20608 传感器，这三部分串下来，就是一个标准 SPI 外设驱动的开发全流程。希望这份整理对你理解 IMX6ULL 的 SPI 通信有所帮助。
