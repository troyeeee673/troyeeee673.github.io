Linux驱动之并发与竞争

发表于 2026-06-28 分类于 Linux系统驱动开发

# 一、并发与竞争简介

## 1.1 什么是并发与竞争？

- *并发（Concurrency）*：多个执行单元（线程、中断、多核CPU）同时访问共享资源。

- *竞争（Race Condition）*：由于并发访问导致共享资源的状态出现非预期结果。

- *并发来源*：

- *多线程/多进程*：多个任务抢占CPU，访问共享数据。

- *中断*：硬件中断可随时打断当前任务，处理程序可能访问相同数据。

- *多核（SMP）*：多个CPU核心真正并行执行，同时操作内存。

- *内核抢占*：内核态任务可被更高优先级任务抢占。

## 1.2 保护的是什么？

- *保护对象：共享数据（临界资源）*。

- *临界区（Critical Section）*：访问共享数据的代码段。必须保证这段代码在同一时刻只被一个执行单元访问。

# 二、并发与竞争解决方法

## 2.1 原子操作

*适用场景*：保护单一的、简单的整数或位运算。开销最小。

### 2.1.1 原子变量操作

Linux内核提供 atomic_t (32位) 和 atomic64_t (64位) 结构体。

```c

atomic_t my_atomic = ATOMIC_INIT(0); // 定义并初始化

```

| 函数 | 描述 | 备注 |

| :— | :— | :— |

| ATOMIC_INIT(int i) | 编译时初始化原子变量。 | |

| int atomic_read(atomic_t *v) | 原子地读取 v 的值并返回。 | |

| void atomic_set(atomic_t *v, int i) | 原子地向 v 写入 i 值。 | |

| void atomic_add(int i, atomic_t *v) | 原子地给 v 加上 i。 | |

| void atomic_sub(int i, atomic_t *v) | 原子地从 v 减去 i。 | |

| void atomic_inc(atomic_t *v) | 原子递增（加 1）。 | |

| void atomic_dec(atomic_t *v) | 原子递减（减 1）。 | |

| int atomic_dec_return(atomic_t *v) | 原子递减，并返回****新值****。 | 注意笔记中是“返回值”，确切说是返回操作后的新值。 |

| int atomic_inc_return(atomic_t *v) | 原子递增，并返回****新值****。 | 同上。 |

| int atomic_sub_and_test(int i, atomic_t *v) | 原子地减 i，若****新值等于 0**** 返回真。 | |

| int atomic_dec_and_test(atomic_t *v) | 原子递减，若新值为 0 返回真。 | |

| int atomic_inc_and_test(atomic_t *v) | 原子递增，若新值为 0 返回真。 | |

| int atomic_add_negative(int i, atomic_t *v) | 原子地加 i，若****新值为负数****返回真。 | |

### 2.1.2 原子位操作

用于操作内存中某个变量的特定位，无需定义原子变量。

```c

// 示例：设置标志位

unsigned long flags = 0;

set_bit(0, &flags);

```

（具体API表你未列出，常与 set_bit, clear_bit, test_bit 等配合使用，用于共享的标志位管理）

## 2.2 自旋锁（Spinlock）

*适用场景*：多核系统、临界区极短、不能休眠的情况（如中断上下文）。等待锁时忙等（自旋），不休眠。

### 2.2.1 基本操作 API

| 函数 | 描述 |

| :— | :— |

| DEFINE_SPINLOCK(spinlock_t lock) | 定义并静态初始化一个自旋锁。 |

| spin_lock_init(spinlock_t *lock) | 动态初始化自旋锁。 |

| void spin_lock(spinlock_t *lock) | 加锁。获取不到则自旋等待。 |

| void spin_unlock(spinlock_t *lock) | 解锁。 |

| int spin_trylock(spinlock_t *lock) | 尝试加锁。成功返回非0，失败返回0（不等待）。 |

| int spin_is_locked(spinlock_t *lock) | 检查锁是否被持有。 |

### 2.2.2 中断安全 API（应对线程与中断的并发）

普通自旋锁不保护中断上下文，需配合中断屏蔽。

| 函数 | 描述 |

| :— | :— |

| void spin_lock_irq(spinlock_t *lock) | *直接禁止本地中断*，然后加锁。 |

| void spin_unlock_irq(spinlock_t *lock) | 解锁，并****直接使能本地中断****。 |

| void spin_lock_irqsave(spinlock_t *lock, unsigned long flags) | ****保存当前中断状态****到flags，禁止中断，再加锁。 |

| void spin_unlock_irqrestore(spinlock_t *lock, unsigned long flags) | 解锁，并****恢复****先前的中断状态。 |

> *推荐使用带 save/restore 的版本*：更安全，因为它不会无条件打开中断，适用于获取锁前中断原本就是关闭的场景。

### 2.2.3 使用自旋锁的注意事项（补充与强调）

- *严禁在临界区休眠/阻塞*：

- 原因：持有锁时内核抢占被禁止，若线程A休眠，CPU切换给线程B，B若也需此锁，将永久自旋，导致****死锁****。

- 禁止调用的API包括：copy_from_user、msleep、可能阻塞的 kmalloc(GFP_KERNEL) 等。

- *持有时间必须短*：否则影响系统实时性和吞吐量。

- *不能递归上锁*：同一条线程重复获取同一把锁，会因自己持有锁不放而自旋至死。

- *多核意识*：编写驱动时必须假设运行在多核系统，使用自旋锁保护。

## 2.3 信号量（Semaphore）

*适用场景*：临界区较长、允许休眠、且不在中断上下文中使用的进程上下文。

### 2.3.1 特点

- *会导致休眠*：适合占用资源较久的场景。

- *不能用于中断上下文*：中断不允许休眠。

- *开销大于原子操作和自旋锁*：频繁切换上下文不适合极短临界区。

### 2.3.2 API 表

| 函数 | 描述 |

| :— | :— |

| DEFINE_SEMAPHORE(name) | 定义一个二元信号量（初值为1）。 |

| void sema_init(struct semaphore *sem, int val) | 动态初始化信号量，可设定初值。 |

| void down(struct semaphore *sem) | *获取（P操作）*。阻塞等待，休眠****不可被信号打断****。 |

| int down_interruptible(struct semaphore *sem) | 获取信号量。进入休眠后****可被信号（如 Ctrl+C）打断****，返回错误码。 |

| int down_trylock(struct semaphore *sem) | 尝试获取，不等待。成功返回0，失败返回非0。 |

| int down_killable(struct semaphore *sem) | 可被致命信号（如 SIGKILL）打断的等待。 (补充) |

| void up(struct semaphore *sem) | *释放（V操作）*。唤醒一个等待的线程。 |

-–

## 2.4 互斥体（Mutex）

*适用场景*：与信号量类似，但语义更严格，是专为实现互斥锁而设计的。推荐在进程上下文中优先使用。

### 2.4.1 特点与规则

- *会导致休眠*，不能在中断中使用。

- *严格的一对一解锁*：哪个线程上锁，必须由它解锁。（信号量允许不同线程解锁）

- *临界区内可休眠*：支持调用阻塞性API。

- *不能递归上锁解锁*。

### 2.4.2 API 表

| 函数 | 描述 |

| :— | :— |

| DEFINE_MUTEX(name) | 静态定义并初始化。 |

| void mutex_init(mutex *lock) | 动态初始化。 |

| void mutex_lock(struct mutex *lock) | 上锁，获取不到则进入不可中断的休眠（TASK_UNINTERRUPTIBLE）。 |

| int mutex_lock_interruptible(struct mutex *lock) | 可被信号打断的等待版本。 (补充) |

| int mutex_trylock(struct mutex *lock) | 尝试上锁，成功返回1，失败返回0。 |

| void mutex_unlock(struct mutex *lock) | 解锁。必须由持有者调用。 |

| int mutex_is_locked(struct mutex *lock) | 判断是否被持有，返回1表示已上锁。 |

-–

## 总结对比表

| 机制 | 持有锁时可否休眠？ | 适用上下文 | 适用临界区大小 | 主要开销 |

| :— | :—: | :— | :— | :— |

| *原子操作* | 不适用 | 所有（中断、进程） | 一个整数/位 | 最小，CPU指令保证 |

| *自旋锁* | *绝对不行* | 所有（中断、进程） | 极小（微秒级） | 忙等，CPU空转 |

| *信号量* | 可以 | 仅进程上下文 | 大（毫秒级以上） | 上下文切换 |

| *互斥体* | 可以 | 仅进程上下文 | 大（毫秒级以上） | 上下文切换 |
