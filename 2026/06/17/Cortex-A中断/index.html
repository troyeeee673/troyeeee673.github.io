Cortex-A 中断

1. Cortex-A 中断原理

中断是处理器响应外设事件的核心机制。对于 Cortex-A 裸机开发来说，需要重点理解三件事：中断向量表在哪里、异常发生后 CPU 跳到哪里、以及如何通过 GIC 找到真正发出请求的外设。

1.1 STM32 中断系统回顾

STM32 属于 Cortex-M 系列，和 Cortex-A 的中断组织方式不同，但可以先用它建立基本概念。

1.1.1 中断向量表

ARM 芯片通常从固定地址开始取指执行。程序开始的位置会存放中断向量表，中断向量表用于描述异常或中断对应的服务函数入口。

对于 STM32 来说，向量表的第 1 项通常存放栈顶指针，后续项存放复位、中断、异常等入口地址。向量表中的入口地址如果配置错误，就会导致 CPU 跳转到错误位置，进而出现中断处理混乱的问题。

1.1.2 中断向量偏移

一般 ARM 处理器默认从 0x00000000 地址开始运行。对于 STM32，用户程序通常链接到片内 Flash 起始地址 0x08000000。如果代码从 0x08000000 开始执行，就需要告诉内核新的向量表位置。

在 Cortex-M 中，这一步通过设置 SCB->VTOR 寄存器完成，也就是把新的中断向量表起始地址写入 VTOR。

1.1.3 NVIC 中断控制器

NVIC 是 Cortex-M 的嵌套向量中断控制器，主要负责：

  • 使能或关闭指定中断。
  • 设置中断优先级。
  • 管理中断挂起、响应和嵌套。

1.2 Cortex-A 中断系统

Cortex-A 的中断系统更接近操作系统使用的模型。CPU 只看到 IRQ、FIQ 等异常入口，具体是哪一个外设触发了中断，需要通过 GIC 进一步查询。

1.2.1 Cortex-A7 中断向量表

Cortex-A 的异常向量表包含 8 类异常入口，其中裸机驱动中最常关注的是 IRQ。与 STM32 不同，Cortex-A 的异常向量表通常需要开发者在启动文件中自行定义。

1.2.2 中断向量偏移

当前裸机例程通常从 0x87800000 开始运行，因此需要把异常向量表基地址设置为 0x87800000。在 Cortex-A 中，这通常通过向 CP15 协处理器的 VBAR 寄存器写入新的向量表基地址来完成。

1.2.3 GIC 中断控制器

Cortex-A 常用 GIC（Generic Interrupt Controller，通用中断控制器）管理中断。GIC 会把中断源分为三类：

  • SGI（Software Generated Interrupt，软件触发中断）：由软件写 GICD_SGIR 等寄存器触发，常用于多核之间通信。
  • PPI（Private Peripheral Interrupt，私有外设中断）：每个 CPU 核私有的中断，通常只能由指定核心处理。
  • SPI（Shared Peripheral Interrupt，共享外设中断）：多个 Core 共享的外设中断，是最常见的外设中断类型。GPIO、串口、定时器等外部中断通常属于 SPI。这里的 SPI 不是串行外设接口总线。

1.2.4 中断号

为了区分不同中断源，GIC 会为每个中断源分配唯一的中断 ID。每个 CPU 最多支持 1020 个中断 ID，编号范围为 ID0~ID1019。

GIC 中断 ID 的典型分配如下：

  • ID0~ID15：分配给 SGI。
  • ID16~ID31：分配给 PPI。
  • ID32~ID1019：分配给 SPI。GPIO 中断、串口中断等外部中断通常位于这一区间。具体哪个 ID 对应哪个外设，由芯片厂商根据 SoC 设计定义。

1.3 IRQ 中断服务函数的编写思路

在 Cortex-A 中，多个外设中断最终都会汇集到 CPU 的 IRQ 异常入口。因此软件需要先实现一个统一的 IRQ 总入口，再由总入口分发到具体外设的处理函数。

1.3.1 统一的 IRQ 总入口

当任意外设（例如定时器、串口、GPIO）产生中断时，CPU 会跳转到固定的 IRQ 异常向量地址，执行统一的 IRQ 入口函数。

这个入口函数通常不直接处理具体外设逻辑，而是先完成现场保护，然后读取 GIC 状态，确认到底是哪一个中断源发出了请求。

1.3.2 查找并运行具体的外设中断服务函数

在 IRQ 总入口中，需要读取 GIC 的 CPU 接口寄存器，例如 GICC_IAR，从中获取当前中断的硬件中断号。

拿到中断 ID 后，就可以把它作为索引，在提前注册好的函数指针数组中查找对应的外设处理函数，例如 uart0_handler()，然后调用该函数完成具体业务处理。

由于 Cortex-A7 会把来自多个外设的中断汇集到 CPU 的 IRQ 信号线上，所以软件必须在总入口中通过 GIC 查出中断源编号，再跳转到各外设独立的处理函数中。这种设计也是现代操作系统中断分发机制的重要基础。

2. 中断例程编写

2.1 编写按键中断例程

本例程中，KEY0 使用 UART1_CTS 这个 IO。需要为 UART1_CTS 编写 GPIO 中断相关代码，包括 IO 配置、中断触发方式配置、中断使能以及中断回调函数注册。

2.2 修改 start.S

启动文件中需要添加中断向量表，并编写复位异常服务函数和 IRQ 异常服务函数。

复位异常服务函数主要完成以下工作：

  • 关闭 I Cache、D Cache 和 MMU。
  • 设置处理器各工作模式下的 SP 指针。要使用 IRQ 中断，必须至少设置 IRQ 模式下的 SP 指针；为了启动阶段更稳妥，也可以统一设置各模式的 SP。
  • 清除 .bss 段。
  • 跳转到 C 入口函数，也就是 main 函数。

  • MRC：将 CP15 寄存器中的数据读取到 ARM 通用寄存器。
  • MCR：将 ARM 通用寄存器中的数据写入 CP15 寄存器。

2.6 i.MX6ULL GPIO 中断设置

GPIO 中断配置通常包括三步：

  • 设置 GPIO 的中断触发方式，也就是配置 GPIO_ICR1 或 GPIO_ICR2 寄存器。触发方式包括低电平、高电平、上升沿和下降沿。本例程中，KEY0 对应的 UART1_CTS IO 设置为下降沿触发。
  • 使能 GPIO 对应的中断，也就是配置 GPIO_IMR 寄存器。
  • 中断处理完成后清除中断标志位，也就是写 GPIO_ISR 寄存器的相应位。GPIO_ISR 采用写 1 清零机制。

2.7 GIC 配置

GIC 侧需要完成以下配置：

  • 使能对应的中断 ID。GPIO1_IO18 对应的外设中断号为 67，换算到 GIC SPI 中断 ID 为 67 + 32 = 99。
  • 设置中断优先级。
  • 注册 GPIO1_IO18 的中断处理函数。
