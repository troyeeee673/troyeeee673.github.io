Linux系统驱动开发之字符设备驱动开发和pinctl、gpio子系统

发表于 2026-06-27 分类于 Linux系统驱动开发

一、Linux驱动开发核心思想

在进行Linux驱动开发时，需要建立以下核心思想，这与裸机开发有本质区别：

  1. 避免直接操作寄存器：Linux运行在带MMU（内存管理单元）的处理器上，操作的是虚拟地址，直接操作物理寄存器地址是不现实的，也是不被允许的。
  2. 遵循驱动框架：Linux内核为各类设备提供了成熟的驱动框架（如字符设备、块设备、网络设备、平台设备等）。开发驱动必须遵循对应的框架，理解并填充框架要求的接口和数据结构。
  3. 一切皆文件：驱动的最终表现就是/dev目录下的设备文件（如/dev/led）。应用程序通过标准的文件操作API（open, close, read, write等）来访问和控制硬件。
  4. 设备树（Device Tree）：在现代Linux内核中，硬件信息（如外设连接在哪个总线、使用哪个引脚）通过.dts文件（设备树源文件）描述，而非硬编码在内核中。驱动通过标准接口从设备树中获取硬件信息。

二、Linux驱动开发分类

Linux驱动主要分为三大类，每一类都对应一套独立的框架体系：

  1. 字符设备驱动：这是最常见、最基础的一类驱动，适用于大多数按字节流进行操作的简单外设，如LED灯、按键、串口、传感器等。
  2. 块设备驱动：主要针对存储设备，如eMMC、SD卡、硬盘等，数据按块进行存取，涉及复杂的缓冲和I/O调度机制。
  3. 网络设备驱动：面向网络通信设备，如以太网卡、Wi-Fi模块等。它与字符/块设备不同，其通信基于网络协议栈，使用套接字（Socket）接口，而非设备文件。

三、字符设备驱动开发基础

1. 应用程序与驱动的交互原理

驱动开发的本质是实现硬件操作，并向应用层提供统一接口。

  • 驱动与应用的分离：驱动运行在内核空间，负责直接控制硬件；应用程序运行在用户空间，通过调用驱动暴露的接口来使用硬件能力。
  • 用户空间与内核空间的交互流程：
    1. 应用程序调用C库提供的API函数（如fopen, fwrite等，遵循POSIX标准）。
    2. C库函数内部会触发一个软中断（陷入），使CPU从用户模式切换到内核模式。
    3. 内核根据系统调用号找到对应的服务函数（如sys_open），进而调用到驱动程序中实现的open函数。

补充理解：每个系统调用都有一个唯一的系统调用号，内核通过这个号来区分不同的请求（如open、read、write等）。

2. 字符设备驱动开发流程

Linux内核将设备抽象为文件，并提供file_operations结构体来建立应用层文件操作与驱动层函数实现之间的映射关系。

  • file_operations结构体：这是字符设备驱动的核心。驱动开发者需要实现如open， release， read， write， unlocked_ioctl等函数，然后将这些函数的指针赋值给file_operations结构体的成员。
  • 映射原理：当应用程序对/dev/led设备文件调用open()时，内核VFS（虚拟文件系统）会找到该设备文件关联的file_operations结构体，并执行其中的.open指向的驱动函数。

开发提示：

  • 驱动最终是被应用调用的，在写驱动的时候要考虑应用开发的便利性。
  • 对于字符设备驱动来说，重点就是编写应用程序对应的open、close、read、write等函数，也就是对file_operations中函数的实现。
（1）字符设备驱动框架

驱动框架主要体现在对file_operations结构体中open, close, read, write等标准接口的具体实现。

（2）驱动模块的加载与卸载

Linux驱动可以编译为内核的一部分，但更常见的做法是编译为内核模块（.ko文件），这样可以动态加载和卸载。

  • 加载驱动：使用insmod或modprobe命令。驱动模块加载时，会执行module_init宏指定的初始化函数。
  • 卸载驱动：使用rmmod命令。卸载时，会执行module_exit宏指定的清理函数。
（3）字符设备的注册与注销

内核通过设备号来识别设备。驱动加载时需要向内核注册设备，卸载时需要注销。

  • 注册设备：使用register_chrdev函数向系统注册一个字符设备。
  • 注销设备：卸载驱动的时候需要使用unregister_chrdev函数注销掉前面注册的字符设备。
（4）设备号详解

设备号是内核识别设备的关键标识，它是一个32位的无符号整数。

  • 类型定义：

    所以dev_t归根结底就是一个32位无符号数。

  • 构成：Linux内核将设备号分为两部分：

    • 主设备号（高12位）：用于区分设备的类型。
    • 次设备号（低20位）：用于区分同一类型下的不同设备实例。

五、Linux设备树（Device Tree）

设备树（Device Tree，简称DT）是一种描述硬件的数据结构，专门用来解决Linux内核中硬编码板级信息导致的混乱。它以树状数据结构描述硬件资源（CPU、内存、外设等），实现硬件描述与内核代码分离。内核启动时动态读取设备树信息，自动加载适配驱动，大幅提升可移植性与硬件兼容性，已成为Linux描述非可发现硬件的标准方案，支撑多平台通用内核。

1. DTS、DTC、DTB三者的关系

  • .dts：相当于.c，就是DTS源码文件。
  • DTC工具：相当于gcc编译器，将.dts编译成.dtb。
  • .dtb：相当于bin文件，或可执行文件。

通过make dtbs编译所有的dts文件。如果要编译指定的dtbs，使用make imx6ull-alientek-emmc.dtb。

（2）节点完整命名格式

节点完整命名必须包含两部分：node-name@unit-address

  • node-name：节点名字，描述设备类型。

六、Pinctrl与GPIO子系统

  • pinctrl子系统：借助pinctrl来设置一个PIN的复用和电气属性。
  • GPIO子系统：使用gpio子系统来使用GPIO。

1. Pinctrl子系统

Pinctrl是Linux内核用来管理芯片引脚（Pin）复用和电气属性的基础设施。在现代复杂的SoC上，一个物理引脚往往有多种功能，pinctrl就是专门解决这个问题的。

（1）引入pinctrl的原因

解决引脚冲突：如果驱动程序各自为政，在初始化时都去直接操作寄存器，想把同一个引脚配置成不同功能，就会发生冲突，导致系统工作异常。pinctrl子系统的出现，就是为了提供一个统一的管理框架，从根本上避免这种混乱。

（2）内核3大核心角色

pinctrl的框架由三大逻辑块构成：

  1. 引脚控制器驱动（Pin Controller Driver）：这是具体干活的部分，由芯片厂商编写，直接读写SoC的引脚配置寄存器。它向上提供统一的硬件抽象，让其他部分无需关心底层寄存器细节。在drivers/pinctrl/目录下，能看到pinctrl-stm32.c、pinctrl-bcm2835.c等各类平台的具体实现。

  2. 核心框架（Pinctrl Core）：这是登记和管理中心，是内核的标准代码。它维护所有引脚、引脚组和功能配置的数据库，负责处理上层来的请求，协调冲突。

  3. 消费者（Consumers）：这是提需求的用户，通常是具体的外设驱动（如I2C、SPI、UART）。它们不直接碰寄存器，而是通过标准接口向核心框架请求一个”引脚配置”。

（3）如何添加一个PIN的信息

在imx6ul-pinfunc.h中找到：

这个宏包含5个参数：<mux_reg conf_reg input_reg mux_mode input_val>

即：0x0090 0x031C 0x0000 0x5 0x0

  1. mux_reg：0x0090。IOMUXC父节点首地址为0x020e0000，因此UART1_RTS_B这个PIN的mux寄存器地址就是：0x020e0000 + 0x0090 = 0x020e 0090。
  2. conf_reg：0x031C。0x020e0000 + 0x031C = 0x020e 031C，这个寄存器就是UART1_RTS_B的电气属性配置寄存器。
  3. input_reg：值为0，表示UART1_RTS_B这个PIN没有input功能。
  4. mux_mode：5表示复用为GPIO1_IO19，将其写入0x020e 0090。
  5. input_val：就是写入input_reg寄存器的值。
  6. 0x17059：写入电气属性配置寄存器的值。

（2）驱动中对GPIO的操作函数
  1. 首先，获取到GPIO所处的设备节点，比如使用of_find_node_by_path。
  2. 获取GPIO编号，使用of_get_named_gpio函数，返回值就是GPIO编号。
  3. 请求此编号的GPIO，使用gpio_request函数。
  4. 设置GPIO为输入或输出，使用gpio_direction_input或gpio_direction_output。
  5. 如果是输入，通过gpio_get_value函数读取GPIO值；如果是输出，通过gpio_set_value函数设置GPIO值。
（3）驱动编写中遇到的问题

申请GPIO失败

  • 原因：申请的那个GPIO被占用了。
  • 解决方法：如果要使用，需要先解除占用或者重新申请其他GPIO。

3. 使用Pinctrl和GPIO子系统实现驱动编写总结

  1. 添加pinctrl信息。
  2. 检查当前设备树中要使用的IO有没有被其他设备使用，如果有的话要处理。
  3. 添加设备节点，在设备节点中创建一个属性，此属性描述所使用的GPIO。
  4. 编写驱动，获取对应的GPIO编号，并申请IO，成功以后即可使用此IO。
